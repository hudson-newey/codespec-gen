# Create CodeSpec

A skill to guide the agent in creating highly reusable, composable, and testable unit-level prompt blocks (CodeSpecs) representing specific code generation tasks/patterns.

## When to Use

- When you want to capture a reusable code generation pattern (e.g., deep cloning, standard validation, custom data transforming).
- When developers wish to import prompt-level code specifications via imports as described in [docs/codespec.spec.md](../../docs/codespec.spec.md).
- To maintain high consistency, quality, and repeatable output when generated by LLMs.

## Procedure

### 1. Requirements Gathering

Ask or determine the following requirements for the CodeSpec:

- **Name**: The base name of the CodeSpec (e.g., `deep-clone`).
- **Description**: What does the code generated by this instruction do?
- **Parameters/Inputs**: What arguments or variables are passed to this CodeSpec? Define their names, types, and defaults.
- **Constraints**: What are the strict rules for the generated code (e.g., language, error handling, performance, whether a non-inlineable callable wrapper is explicitly required)?
- **Examples**: What is an example inputs-to-code mapping?

Unless the requester explicitly says otherwise, treat the generated code as inlineable at the call site. That means the default output should be an implementation snippet, expression, or statement block that can be inserted directly into an enclosing scope, not a top-level callable function declaration. Inline helper functions are allowed when they are local to that snippet and remain callable from within the enclosing generated context.

### 2. File Location

- File name must match the pattern `[name].codespec.md` (e.g., `deep-clone.codespec.md`).
- It can be located anywhere in the codebase, typically adjacent to the module/file importing it, or in a centralized directory.

### 3. Creating the CodeSpec File

Construct the `.codespec.md` file using the following standard template:

````markdown
---
name: <kebab-case-name>
description: "<Clear description of what this codespec instructs the model to do>"
argument-hint: '<Optional hint/parameters format shown for slash invocation, e.g. "param1: string, param2: number">'
user-invocable: true
---

# <Title of CodeSpec>

<Detailed description of what code this specification generates.>

## Parameters

- `<parameter_1>`: <Type and explanation>
- `<parameter_2>`: <Type and explanation>

## Generation Rules

- **Language/Environment**: <e.g., TypeScript/JavaScript, ES6+, Web API>
- **Behavior**: <Step-by-step logic of what the generated code must do>
- **Inlineability**: Unless explicitly requested otherwise, generate inlineable code for direct insertion at the usage site instead of wrapping the behavior in a top-level callable function. Local helper functions are acceptable if they stay within the generated snippet.
- **Performance/Complexity**: <e.g., O(N) time complexity, minimal allocations>
- **Error Handling**: <e.g., throw on null, return null, return fallback>

## Expected Output

Provide precise instructions on the shape of the code, or a structural outline.
Unless the CodeSpec explicitly asks for a callable export or named function, assume the generated code will be inlined into surrounding code.
When invoked, only output the requested implementation code enclosed in a markdown block.

## Examples

You can include one or more numbered examples when they help clarify the intended transformation.

### Example Input 1

````json
{
  "<parameter_1>": "value"
}
\```

### Output 1
```typescript
// Example of compliant generated code
\```

### Example Input 2

````json
{
  "<parameter_1>": "another value"
}
\```

### Output 2
```typescript
// Optional second compliant generated code example
\```
````
````

### 4. Verification and Clean Up

- Ensure YAML syntax in the frontmatter is correct and properly escaped.
- Verify the file is successfully written with the `.codespec.md` extension.
- Verify the CodeSpec makes the default inlineability expectation clear unless the requested behavior genuinely requires a callable wrapper.
